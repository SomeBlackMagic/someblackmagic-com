Реліз [Jinja2 Enhanced Support](https://plugins.jetbrains.com/plugin/29804-jinja2-enhanced-suppo) 20206.3.2 майже повністю присвячений розширюваності. Плагін тепер краще розуміє шаблони «з коробки», а фреймворкам і бібліотекам стало простіше навчити його своїх правил: як шукати шаблони, які фільтри доступні і яких типів змінні. Нижче про головне.

## Template Resolver API: шаблони там, де їх шукає ваш фреймворк

У кожного фреймворку свої правила пошуку шаблонів: префікси застосунків, неймспейси, кілька каталогів, віртуальні шляхи. Раніше плагін міг тільки вгадувати. Тепер є **Template Resolver API** (`Jinja2TemplateResolver`), через який розширення:

- перетворює рядок у `{% include %}`, `{% extends %}` чи `{% import %}` на реальний файл;
- пропонує власне автодоповнення шляхів;
- «забирає» шлях собі: якщо resolver визнав шлях своїм, інші механізми не втручаються, а якщо ні, діє звичайна логіка пошуку.

Разом з API з'явилася **інспекція невирішених шаблонів**. Вона підсвічує шляхи, які ніхто не зміг вирішити, і окремо позначає динамічні вирази, які статично перевірити не можна. Інспекція не заважає там, де посилання на відсутній файл зроблене свідомо:

- `{% include "optional.html" ignore missing %}` вона не чіпає;
- у списку запасних варіантів, наприклад `{% include ["custom.html", "default.html"] %}`, вона не скаржиться на відсутній перший файл, якщо знайшовся запасний.

## Навігація з кількома цілями

Буває, що один шлях вказує одразу на кілька файлів: перевизначені шаблони, кілька каталогів, різні теми. Тепер у такому разі Go to Declaration показує список, де кожна ціль має свій опис та іконку. Так легко зрозуміти, куди саме ви переходите.

## Точніше розуміння посилань: `user.address["city"]`

Ми переписали аналіз ланцюжків доступу. Тепер вираз розбивається на сегменти, і кожен зберігає свій синтаксис: звернення через крапку, індекс або рядковий ключ. Кожне PSI-посилання знає, на який саме сегмент воно вказує. Ключі в лапках декодуються, тож `data["my-key"]` і `data['my-key']` розпізнаються однаково.

Для вас це означає точніші автодоповнення, навігацію та підказки типів у довгих виразах. Для авторів розширень з'явилися `Jinja2AccessSegment`, `referenceSegmentIndex` і новий контекст для тегів присвоєння (`Jinja2AssignmentTagContext`).

## Висновок типів, що не губиться по дорозі

Раніше тип змінної часто губився після першого ж перетворення. Тепер він проходить через:

- присвоєння (`{% set %}`);
- звернення за індексом;
- фільтри;
- виклики функцій і макросів;
- умовні вирази.

```jinja
{% set first = users | first %}
{% set name = first.name if first else "Guest" %}
{{ name | upper }}   {# плагін знає, що це рядок #}
```

## Застарілі фільтри й тести

Фільтр або тест тепер можна позначити як deprecated і додати метадані: чим його замінити і з якої версії він застарів. Плагін перекреслить його в редакторі, покаже попередження інспекції і врахує це при навігації та висновку типів. Це зручно для бібліотек, які поступово оновлюють свій API.

## Metadata Source API і `.jinja2-metadata.json`

Найбільша новинка релізу: декларативний **Metadata Source API**. Тепер змінні, фільтри, тести, функції та їхні типи можна описати у файлі метаданих, і для цього не потрібно писати плагін.

Вбудовано підтримку файлу `.jinja2-metadata.json`:

- для нього є JSON Schema, тож автодоповнення та валідація працюють прямо в IDE;
- файл відстежується через VFS, і зміни підхоплюються одразу, без перезапуску та переіндексації вручну;
- створити його можна з шаблону *New → File*.

Цей формат підійде командам, які хочуть описати контекст своїх шаблонів (наприклад, змінні, які передає бекенд) і отримати повноцінні підказки.

## Символи з прив'язкою до файлів: `appliesTo`

Провайдери фільтрів, тестів і функцій тепер можуть вказати через `appliesTo`, до яких файлів вони застосовуються. Специфічні для фреймворку фільтри з'являтимуться тільки в шаблонах цього фреймворку і не засмічуватимуть автодоповнення в інших проєктах. Крім того, додано утиліту, яка знаходить файл-хост для шаблонів, вбудованих в інші мови.

## Під капотом

- **`Jinja2ProviderLifecycle`**: єдиний механізм інвалідації кешів і переіндексації для всіх провайдерів. Кожен провайдер отримав `ModificationTracker`, тож дані оновлюються вчасно і без зайвих перерахунків.
- **Оригінальні координати в контексті автодоповнення.** Тепер провайдер знає точну позицію курсора у вихідному файлі, навіть якщо шаблон вбудований в іншу мову.
- Оновлено процес релізу: збирання в контейнері та покращена інтеграція з Sentry. Також виправлено конфігурацію ProGuard для нової інспекції.

## Для авторів розширень

Усі нові API задокументовано: є окремі гайди щодо resolver'ів, приклади та тести. Старі провайдери типів працюють як раніше, бо `resolveType` залишився сумісним.

Оновлюйтеся через *Settings → Plugins* або на [сторінці плагіна в JetBrains Marketplace](https://plugins.jetbrains.com/plugin/29804-jinja2-enhanced-suppo) і пишіть нам, що ще варто покращити.
